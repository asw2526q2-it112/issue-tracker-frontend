# AGENTS.md — Issue Tracker Frontend

**Read [`README.md`](./README.md) first.** It has the stack, folder layout, scripts, theme, API auth, and team workflow. This file only adds the agent-specific rules and the Next.js 16 quirks worth flagging.

## Always-true rules

- **Don't edit `src/lib/api/schema.ts`** — auto-generated by `pnpm api:types` from `../issue-tracker/api/api.yml`. Regenerate when the OpenAPI schema changes.
- **Don't call `fetch` directly** — use `api` from `@/lib/api/client`. It's typed against the OpenAPI paths and injects auth automatically.
- **Don't inline query keys** — extend `qk` in `@/lib/query/keys.ts` so invalidations stay consistent.
- **Forms use react-hook-form + zodResolver** with a schema from `features/<name>/schemas.ts`. Don't roll your own validation.
- **Reach for shadcn primitives first** (`src/components/ui/`). If something's missing, run `pnpm dlx shadcn@latest add <name>` rather than writing a custom one.
- **No ad-hoc hex colors.** Extend the CSS variables in `src/app/globals.css`.

## Next.js 16 specifics (defends against stale training data)

- `params` and `searchParams` in pages/layouts are now **Promises** — `await` them.
- App Router only — no `pages/` directory.
- Server Components by default; add `"use client"` only when you need hooks, state, or event handlers.
- Cache Components and PPR are available; default to standard SSR/SSG unless you have a reason otherwise.
